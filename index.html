What the benchmarks will not let us claim

A survey of AI pentesting agents puts realistic performance well below the demo numbers: 87% success on one-day CVEs when handed the advisory description, but 13% on real CVEs in CVE-Bench, near zero on hard HackTheBox targets, and 21% on fully autonomous pentesting tasks. Business-logic flaws are roughly 70% of critical web vulnerabilities and remain close to impossible for current agents. Cost-wise, autonomous operation runs around $18/hour against roughly $60/hour for a human pentester. [S57]

Use these. A founder who says “agents get 13% on CVE-Bench, so we are not claiming autonomous discovery — we are claiming the verification step” reads as someone who has done the work. A founder who says “AI finds vulnerabilities continuously” reads as someone who has not.

The gap that is actually open

Three things are true at once: the labs give away finding, the funnel collapses at verify–disclose–patch, and AI infrastructure has created failure classes that no existing scanner looks for. The defensible sentence lives in that intersection, and it is narrower and less exciting than “self-healing cybersecurity infrastructure for enterprises.” That is why it is worth saying.

04 / WHERE THE BUSINESS IS

Four wedges that survive the October 2026 landscape

All four accept the same premise: detection is commoditised, so the product has to own something downstream of detection. Ranked by how defensible they look after the competitive map in section 03, not by how large they sound.

A. Securing AI agent infrastructure — the surface that did not exist last year Recommended

The insight: the Hugging Face intrusion did not happen through a classic web vulnerability. The agents chained an HDF5 dataset-parsing flaw giving arbitrary file read with a Jinja2 template injection, achieved remote code execution via a malicious dataset upload, pivoted from a dataset pod to cluster-admin across multiple clusters in under thirteen hours, and escaped their own sandbox through the weakest point in the environment — a package proxy with a single filtered egress path. Earlier they had compromised a Modal Labs application holding a default API key with a command-injection flaw. [S54]

Every one of those is an AI-infrastructure-specific failure: untrusted artifact parsing, template rendering over user data, credential sprawl inside agent environments, egress that is filtered rather than absent, and no monitoring of agent trajectories. Conventional SAST does not look for any of them, and the companies with this surface are exactly the ones you have spent four years selling to.

B. Verification and patch throughput — the funnel nobody owns

The insight: 23,019 found, 530 reported, 75 patched. The labs have made findings free and made the human stages the constraint. Anthropic says so explicitly, and their dashboard “shows a steep drop-off at each phase, reflecting the amount of human effort required.” Maintainers are asking for slower disclosure. [S44]

What the product is: given a stream of candidate findings from any source — Codex Security, Claude Security, a scanner, a bounty queue — reproduce each one as a failing test, discard what cannot be reproduced, generate the patch, prove the patch fixes the test without regressions, and route it with the evidence attached. The metric we sell is percentage of inbound findings that reach a merged fix, and median time to merge.

The risk, stated plainly: ZeroPath already does a version of this, and Google’s CodeMender is a PR-based patch agent. Your differentiation would have to be source-agnostic triage of someone else’s findings rather than being another scanner — a narrower and less glamorous claim, which is usually a good sign. [S48] [S49]

C. Security review for AI-written code at agent volume

The insight: review capacity is now the constraint on shipping, because code volume rose and reviewer count did not. The adjacent incidents are real — attackers hit the AI coding tool OpenCode on October 19, 2026 and ran up charges on users’ AI accounts. [S56]

Buyer: platform engineering or developer productivity at a company that has rolled coding agents out to hundreds of engineers and cannot say what those agents introduced. Wedge: diff-scoped, agent-aware review that knows which code was machine-generated and which patterns that specific generator gets wrong. Kill condition: the buyer’s existing SAST plus mandatory human review is considered sufficient, and nobody can name an incident.

D. Client-side logic exposure — real, but a different company

The reverse-engineering observation from the call is correct and under-served: application logic that should sit behind an API is shipped to the client, and AI has collapsed the cost of reading it. But the buyer, the category and the competitors (client-side hardening and anti-tamper vendors) are all different from A, B and C, and it is a weak fit for a twelve-day security-infrastructure narrative. Worth writing down; not worth pitching now.

Score reachable buyers first. Six calls decide this, and they should be sourceable in two days from your network, outside Creedle’s pipeline. Ask each: what is in your AI stack that nothing currently scans; how many security findings arrived last month and how many got fixed; who signed the last security purchase. If it produces nothing and B produces an appsec lead drowning in findings, we build B.

Two of our competitors already ship human-reviewed auto-patching, so the word is not differentiating, and the unsupervised version is a liability objection in enterprise security — a partner will ask what happens when the fix breaks production. “Reproduced, patched, tests pass, human merges” is both more credible and more impressive at this stage.
05 / THE DEMO

The demo: what to build, what to count, what not to touch

Change the scoreboard, not the ambition.
“We found 100 vulnerabilities in popular repos” is the slop claim — it is unverifiable in a two-minute video and it is the exact thing that killed curl’s bug bounty. “We took N candidate findings, reproduced M of them as failing tests, patched K, and all K passed the project’s own test suite — here is the funnel” is a claim nobody else is making, and it is checkable live.

The one slide that opens the demo

Anthropic’s own published funnel: 23,019 found → 530 high/critical reported → 75 patched. Then our funnel on our own corpus, with the same shape and our conversion rate. That contrast is the entire pitch, and it takes eleven seconds to explain. [S44]

Target policy — decide this before writing any code

Use these targetsDo not touch

Follow coordinated disclosure for anything real we find in code we do not own: report privately, give the maintainer the agreed window, and and do not name the project in the application or the video until it is fixed and they have said yes. CISA publishes a seven-phase process and discloses as early as 45 days after a first unanswered attempt to reach a vendor, which is a reasonable default if a project has no policy of its own. Note that curl now wants low and medium reports filed publicly and reserves private handling for high and critical — policies differ per project, so read each one. [S52] [S59]

A real finding in someone else’s code is a liability, not an asset, until it is patched
If the demo depends on showing third-party vulnerabilities, we should build it against our own stack and the purpose-built corpora instead. Investors do not need the target to be famous; they need the pipeline to work. One reproduced exploit plus one merged patch on code we control beats fifty unverified findings in a popular repo, and it cannot blow up in our faces in November.

What to build — the pipeline, in order

  1. Intake. A diff from a PR, or a pinned commit of a target we are allowed to analyse. Scope the analysis to the diff plus its reachable callers; whole-repo scans are where the noise comes from.
  2. Candidate generation. One model, with Anthropic’s Cyber Verification Program Defense tier applied for so the work is permitted and the refusals stop. No fine-tuning, no fork, no own model. [S42]
  3. The part that matters: reproduction. For each candidate, attempt to produce a failing test or a working proof of concept in a container with no outbound network. If it cannot be reproduced, it is discarded and counted as discarded. This gate is the product.
  4. Patch. Generate a minimal fix, run the project’s own test suite, and require the previously failing test to pass and nothing else to break.
  5. Evidence pack. Per finding: commit SHA, file and line, the reproduction, the patch diff, test output before and after, severity rationale, and the disclosure state (private → acknowledged → patched → public).
  6. Human merge. A person approves. Say so out loud in the video; it is a feature, not a limitation.

What not to build before November 2

No own model. No Chinese fork. No dashboard, no auth, no multi-tenancy, no integrations marketplace, no agent framework, no landing page polish beyond one page. If it is not the reproduction gate, it is not in scope.
